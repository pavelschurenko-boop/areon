# YouScore Registration Data Checker

## Призначення
Внутрішній інструмент для спеціалістів служби підтримки. Дозволяє ввести код
ЄДРПОУ (або РНОКПП ФОП) і отримати повну інформацію з Єдиного державного
реєстру України через API YouScore (YouControl) — метод «Реєстраційні дані»
(Registration data). Результат показується інформативно: як позитивні дані
(компанія активна, реквізити, керівники тощо), так і негативні (банкрутство,
припинення діяльності, помилки, компанію не знайдено).

## Файли
- `index.html` — сам інструмент (одностраничний HTML/CSS/JS, без збірки).
  Хоститься на GitHub Pages.
- `worker/` — Cloudflare Worker, який проксіює запити до YouScore API і
  ховає API-ключ (GitHub Pages віддає лише статичні файли, тому ключ не може
  жити на клієнті). Див. `worker/README.md` для деплою.

## API, який використовується
- **Реєстраційні дані**: `GET https://api.youscore.com.ua/v1/usr/{contractorCode}?showCurrentData=false&apiKey={API_KEY}`
- **Податкові дані (ПДВ)**: `GET https://api.youscore.com.ua/v1/vat/{contractorCode}?showCurrentData=false&apiKey={API_KEY}`
  — статус платника ПДВ (ІПН, дата реєстрації, примітка).
- **Ліцензії**: `GET https://api.youscore.com.ua/v1/licenses?contractorCode={code}&apiKey={API_KEY}`
  — список ліцензій контрагента (статус, вид діяльності, номер, строк дії,
  орган видачі, реєстр). На відміну від інших методів код передається як
  query-параметр, а не як частина шляху. Дані не оновлюються за запитом
  (`showCurrentData` тут не застосовується). Підтримує пагінацію
  (`top`, `skip`, за замовчуванням до 100 записів) та фільтр `registers`/
  `onlyActive` — проксі їх пропускає, але фронтенд поки їх не використовує
  (завжди перша сторінка, дефолтні параметри YouScore).
  (усі три методи викликаються з Worker, не напряму з браузера).
- `contractorCode` — код ЄДРПОУ юрособи або РНОКПП/паспорт ФОП, вводиться користувачем.
- `showCurrentData=false` — завжди отримувати актуальні (не архівні) дані (для `usr`/`vat`).
- Відповідь `/usr`: JSON з даними компанії (назва, код, статус, адреса, контакти,
  засновники, підписанти, види діяльності КВЕД, статутний капітал, дані про
  банкрутство/припинення тощо). Структура відповіді описана у Swagger:
  https://api.youscore.com.ua/swagger/index.html
- Коди помилок: 400 — невірний формат коду, 404 — не знайдено, 429 — перевищено
  ліміт запитів (200/хв, 50/5с на ключ), 401/403 — проблема з ключем, 202 —
  дані оновлюються (показується окремим банером для всіх трьох методів).
- YouScore також має окремі методи `/v1/vatCanceled`, `/v1/singleTax`,
  `/v1/taxDebt` для інших податкових даних — поки не підключені (див.
  "Відомі обмеження" нижче).

## Поточний стан
- Поле вводу коду + три кнопки: «Реєстраційні дані» (`/usr`, і обробка Enter),
  «Податкові дані (ПДВ)» (`/vat`), «Ліцензії» (`/licenses`).
- Гарний, сучасний дизайн (картки, бейджі, кольорові статус-банери).
- Секції результату: основна інформація, статус/реєстрація, адреса/контакти,
  статутний капітал, види діяльності, керівники/підписанти, засновники,
  окремий блок «негативні фактори» (банкрутство, припинення, відсутність
  бенефіціарів тощо); для ліцензій — список зі статусом (діюча/недіюча),
  реєстром, органом видачі та строком дії.
- Технічна інформація про запит (HTTP статус, заголовки відповіді, час
  виконання) — окремий розгортний блок для кожного результату.
- Розгортний блок з повним сирим JSON відповіді.
- Обробка помилок 400/404/429/202/мережевих помилок з людськими повідомленнями.
- API-ключ винесено на бекенд-проксі (Cloudflare Worker) — не видно у
  вихідному коді сторінки.

## Відомі обмеження / що варто допрацювати далі
1. Немає обробки типів контрагента, відмінних від юрособи (ФОП, відокремлені
   підрозділи, органи влади) — у Swagger вказано, що схема відповіді
   відрізняється залежно від типу контрагента. Варто додати гілки рендерингу
   під ці типи (branches, authorityInfo для органів влади тощо).
2. Немає валідації формату введеного коду на фронтенді до відправки запиту.
3. Метод «Ліцензії» не має пагінації в UI — якщо ліцензій більше 100,
   показується лише перша сторінка (`nextPageUrl` видно тільки в сирому JSON).
